# 架构设计

## 领域模型

服务器预配置最多五个 `User`。每个用户拥有一个 `Room` 和一只 `Pet`。用户当前观看的房间始终等于自己的桌宠所在房间，因此串门后客户端自动切换到目标房间。

```text
User.currentRoomId == User.pet.currentRoomId
Room.ownerUserId   == User.userId
```

房主在线但外出时，`allowVisitsWhileOwnerAway` 决定房间是否继续接待访客。房主离线时房间始终关闭。

## 坐标同步

每个房间使用独立的 `[0,1] × [0,1]` 归一化坐标。桌面客户端把位置映射到主显示器物理坐标：

```text
pixelX = monitorLeft + normalizedX × monitorWidth
pixelY = monitorTop  + normalizedY × monitorHeight
```

不同分辨率和 DPI 下保持相对位置一致。服务器不接收显示器分辨率，也不传输任何桌面像素。

## 客户端

控制中心由 Tauri WebView 中的 React 渲染，但它只负责设置、图片生成和网络连接。每只可见桌宠对应一个 WPF 透明、无边框、置顶、跳过任务栏的独立 Windows 原生窗口；桌宠窗口不包含网页或房间画面。

控制中心维持唯一 WebSocket 连接，将服务器快照经本机标准管道发送给一个轻量原生桌宠宿主。宿主管理最多五个桌宠窗口、拖拽、右键动作菜单、骨骼动画和自主行为调度，并把拖拽/互动/自主移动事件通过同一管道返回控制中心。因此设置窗口隐藏时，随机游走不依赖 WebView 计时器。自主行为在用户设置的最短/最长秒数之间均匀随机取值；桌宠完成匀速移动后才开始下一轮静止计时。

素材界面有八个固定部件：圆形头、胶囊状躯干、双臂和双腿，以及可选的圆弧三角形双耳。每个部件可单独选择图片并按虚线形状中心填满裁切，或使用纯色。生成包始终绑定同一套九骨骼（含 `root`）；桌面显示时将各图层栅格化为 PNG，原生宿主只接收图片和声明式状态，不执行用户代码。

## 服务器

服务器是单 Node.js 进程：

- HTTP：登录、房间快照、素材上传与下载、健康检查。
- WebSocket：房间快照、移动、拖拽、动作、互动和串门。
- 内存：在线状态、房间成员、拖拽锁和动作状态。
- 文件存储：用户显示名、权限、素材版本和最多五个桌宠包。

每个房间有独立递增 `sequence`。客户端只订阅自己当前所在房间；其他房间仅通过成员摘要显示在线/外出状态。

## 断线语义

连接断开后用户进入 15 秒 `reconnecting` 状态。其个人房间暂停新准入，但当前状态暂时保留。宽限期结束后：

1. 移除离线用户桌宠；
2. 关闭其个人房间；
3. 把其中所有访客迁回各自房间；
4. 广播受影响房间的新快照。

## 扩展边界

`MAX_USERS` 和 `MAX_PETS_PER_ROOM` 当前为 5，但房间、用户和桌宠均使用 ID 建模。扩展到多个服务器时，可将状态管理器替换为数据库和 Redis，并以 `roomId` 进行分片；客户端协议无需改变核心语义。
